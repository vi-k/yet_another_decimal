# Решения по 2.0 и план 1.3.0

## Что решил владелец

| | Вопрос | Решение |
|:--|:--|:--|
| Q1 | `operator /` | **не трогать.** Остаётся быстрой формой, которая бросает. Обоснование слома («заглавный API — самый медленный путь») закрыто в 1.2.0 аддитивно |
| Q2 | неизменяемость `Decimal` | **аддитивно:** чистый `normalized()`, `optimize()` помечается устаревшим. Поля кеша остаются, `@immutable` не ставится |
| Q3 | открытое представление | **открыть, от канонической формы** |
| Q4 | `int.toDecimal()` | **убрать наше** — через устаревание |
| Q5 | `FixedPoint` | **остаётся внутренним** |
| Q6 | единый тип исключения при делении на ноль | **в 1.3.0** |
| Q7 | форма релиза | **1.3.0 сейчас, 2.0 без даты** |

**Следствие.** Из шести пунктов, отложенных спекой на 2.0, ломающих не осталось
ни одного из тех, ради которых мажор затевался. 2.0 сводится к удалению двух
членов, которые к тому времени год пролежат помеченными `@Deprecated`. Даты у
неё нет и не нужно: повод найдётся сам.

Два решения — Q1 и Q5 — это решения **ничего не делать**, и они закрывают
вопросы, а не откладывают их. `operator /` бросает по замыслу; `FixedPoint`
работает на компилятор, а не на пользователя.

## Что входит в 1.3.0

Всё аддитивно, кроме пункта 5, который ломает только тех, кто ловит
устаревший тип исключения.

### 1. Раздельные точки входа

`lib/decimal.dart` и `lib/short_decimal.dart` рядом с общей
`lib/yet_another_decimal.dart`. Кому нужно одно семейство, не тянет второе.

Мост (`lib/src/bridge.dart`) остаётся только в общей точке: он по определению
про оба.

### 2. `normalized()` вместо `optimize()`

```dart
@Deprecated('Use normalized() instead: it returns a value rather than mutating')
void optimize();

Decimal normalized();
```

`normalized()` возвращает значение в канонической форме и ничего не мутирует.
У `ShortDecimal` он тоже появляется и возвращает `this`: представление там
канонично всегда. Это делает член общим, и он уходит в `FixedPoint` — иначе
пришлось бы записывать расхождение.

`optimize()` живёт помеченным до 2.0.

### 3. Открытое представление

`unscaledValue` и `exponent`, **от канонической формы**: два равных значения
обязаны отдавать одинаковую пару, иначе наружу протекает артефакт последней
операции.

- `exponent` — `int` у обоих, уходит в `FixedPoint`;
- `unscaledValue` — `BigInt` у `Decimal`, `int` у `ShortDecimal`, значит в
  интерфейсе не выражается и попадает в список расхождений **по типу** в
  `test/symmetry_test.dart`, рядом с `inverse` и `divideToFraction`.

`base` и `scale` остаются `@visibleForTesting`: они про хранение, а новые
геттеры — про значение.

### 4. Читаемые синонимы к `<<` и `>>`

Операторы остаются. Добавляются имена, которые не надо расшифровывать:

| Оператор | Синоним | Что делает |
|:--|:--|:--|
| `value >> n` | `value.movePointLeft(n)` | делит на `10^n` |
| `value << n` | `value.movePointRight(n)` | умножает на `10^n` |

Имена взяты у `BigDecimal` из Java — там та же операция называется так же.
Заодно они снимают главную причину путаницы: `>>` в десятичной семантике
двигает точку **влево**, а не вправо, и это ровно то, что сбивает читателя.

### 5. Единый тип исключения при делении на ноль

`~/`, `%` и `remainder` в обоих семействах переводятся с
`IntegerDivisionByZeroException` на `UnsupportedError` — тот же тип, что уже
бросает `operator /` и `Fraction`.

Проверено прогоном: сейчас `Decimal ~/ 0`, `% 0`, `remainder(0)` и оба
`ShortDecimal`-аналога бросают устаревший тип, а `/ 0` — новый.

Мягкость перехода: в SDK `IntegerDivisionByZeroException` помечен
`@Deprecated("Use UnsupportedError instead")` и **реализует** `UnsupportedError`.
Кто ловит `UnsupportedError`, ничего не заметит; сломается только тот, кто
ловит устаревший тип поимённо.

### 6. `@pragma('vm:deeply-immutable')` для `ShortDecimal`

Проверено: класс из двух `final int` пригоден, `Expando` на таком объекте
работает, `const`-конструкторы не мешают. Даёт право на разделяемую память
между изолятами.

`Decimal` этого права не получит никогда: компилятор отвергает поле типа
`BigInt` — «Deeply immutable classes must only have deeply immutable instance
fields». Асимметрия объясняется в коде.

### 7. Устаревание `toDecimal()` на `int` и `BigInt`

```dart
@Deprecated('Conflicts with the same extension from package:decimal. Use Decimal(3) / Decimal.fromBigInt(v)')
```

Оба наших расширения конфликтуют с одноимёнными из `decimal`, у которого они
есть и на `int`, и на `BigInt`: два пакета рядом не соберутся. `toShortDecimal`
не конфликтует и остаётся без пометки.

Удаление — в 2.0.

## Порядок

Пункты независимы, кроме одного: **2 и 3 трогают `FixedPoint`**, значит идут
до того, как обновится тест симметрии, — или вместе с ним.

Разумная нарезка на два захода:

1. **API:** `normalized()`, представление, синонимы, устаревания (1, 2, 3, 4, 7).
2. **Поведение и сборка:** тип исключения и прагма (5, 6).

## Готово, когда

- `dart analyze` чист, `dart format` чист, все тесты зелёные на Dart 3.13 **и
  на Dart 3.6.0** — порог проверяется прогоном, а не декларацией;
- покрытие `lib/` не ниже нынешних 100 % строк;
- тест симметрии зелёный: каждый новый член либо в `FixedPoint`, либо в списке
  расхождений;
- `dart pub publish --dry-run` без предупреждений, `pana` не ниже 160/160;
- в `CHANGELOG.md` раздел 1.3.0, где про каждое устаревание сказано, чем
  заменять;
- README знает про раздельные точки входа и про синонимы.

## Риски

| Риск | Что делать |
|:--|:--|
| Раздельные точки входа плодят три способа импортировать одно и то же | общая точка остаётся главной и подаётся первой в README; раздельные — для тех, кому нужен один тип |
| `normalized()` на `ShortDecimal` — метод, ничего не делающий | так и документировать: форма там канонична всегда, метод есть ради общего контракта |
| Открытое представление замораживает устройство | заморожена только **каноническая** форма, а она и так часть контракта: от неё зависит `==` и `hashCode` |
| `movePointLeft`/`movePointRight` разойдутся с операторами | синонимы делаются вызовом операторов, а не копией логики |

## Чего в плане нет

- **2.0.** Даты нет. Когда появится повод — удалить два устаревших члена, и
  это весь мажор.
- **Слома `operator /`,** публичного `FixedPoint`, неизменяемого `Decimal`,
  `const`-конструкторов, смешивания семейств, отказа от молчаливого
  переполнения `ShortDecimal`. Всё это решено — «нет».

## Отдельно: когда выпускать

План исходит из того, что 1.2.0 выходит первой, а 1.3.0 идёт следом. 1.2.0
готова, проверена и ждёт только разрешения на публикацию.

Альтернатива — влить аддитивное прямо в неопубликованную 1.2.0 — возможна, но
задерживает готовый релиз ради того, что и так выйдет минором. Решать владельцу.
