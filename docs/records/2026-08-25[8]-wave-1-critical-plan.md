# Волна 1. Четыре критических дефекта

Критерий готовности каждого — снятие `skip` с его теста в
`test/defects_test.dart`. Плюс два теста в `property_test.dart` и
`competitors_test.dart`, помеченные Д1.

## Д1. Деление на отрицательное бросает вместо результата

`operator /` раскладывает делитель на двойки и пятёрки циклами
`while (divisor % 5 == 0)`. У Dart остаток от деления неотрицателен, поэтому
для отрицательного делителя разложение останавливается на `-1`, а не на `1`,
и метод бросает `DecimalDivideException` там, где результат представим:
`Decimal(1) / Decimal(-2)` вместо `-0.5`.

**Правка:** вынести знак делителя до циклов — `base = -base; divisor = -divisor`.
Оба семейства.

## Д2. `_pow10` переполняется молча

`static int _pow10(int e) => math.pow(10, e) as int` — при `e >= 19` даёт
обёрнутое по модулю 2^64 число, причём `10^19` оборачивается в
**отрицательное** `-8446744073709551616`. Замерено запуском.

Отсюда ломается всё, что выравнивает масштабы:

| Где | Что происходит |
|:--|:--|
| `_align` → `compareTo`, `==`, `<`, `<=`, `>`, `>=` | сравнение с домножением на отрицательное; `0.000000000000000001 < 10` даёт `false` |
| `_dropFraction` → `floor`, `round`, `ceil`, `truncate`, `toStringAsFixed` | делитель отрицателен, округление почти-нуля даёт мусор |
| `toInt` | то же через `truncate` |

Важно: **порог не в разрыве масштабов, а в переполнении произведения.**
Разрыв в 5 тоже переполняет, если база велика: `9·10^18` против `1·10^-5`.
Поэтому проверять надо само произведение, а не только показатель.

**Правка, три части.**

1. **Таблица степеней.** `_pow10` для `0..18` берёт значение из
   `const List<int>`. Это заодно первый пункт волны 3 (П2). Для показателя
   больше 18 остаётся сегодняшний `math.pow` с `TODO`: единственный оставшийся
   его потребитель — `ShortFraction`, а это Д11 из волны 2. Менять там
   молчаливое переполнение на `RangeError` в волне 1 — расширение объёма.

2. **Сравнение не через `_align`.** Заводится приватный `_compare`, через
   который идут `compareTo`, `==` и все четыре оператора. Если домножение не
   помещается в int64, ответ известен без него: домноженная сторона по модулю
   больше всего, что вообще записывается базой, а вторая сторона уже записана.
   Значит знак ответа определяется знаком той стороны.

3. **Округление знает про непомещающийся делитель.** Когда
   `10^(scale - fractionDigits)` не помещается в int64, частное заведомо ноль,
   а остаток — вся база. Ответ определяется правилом метода:

   | Метод | Ответ |
   |:--|:--|
   | `truncate` | `0` |
   | `floor` | `-1` для отрицательных, иначе `0` |
   | `ceil` | `1` для положительных, иначе `0` |
   | `round` | `±1`, если `|base| >= 5·10^18` **и** показатель ровно 19; иначе `0` |

   Показатель 19 — единственный, при котором половина делителя ещё помещается
   в int64 и округление может дать не ноль: `10^19 / 2 = 5·10^18`, а
   `int.max ≈ 9.22·10^18`. При показателе 20 и больше `2·|base|` заведомо
   меньше делителя.

`_align` остаётся как есть: им пользуются `~/`, `%`, `remainder`,
`divideToFraction` и `ShortDivision`, где переполнение — настоящее, а не
промежуточное. Решение владельца: молчаливое переполнение `ShortDecimal`
остаётся, чинятся только случаи, где аргументы и канонический результат в
int64 укладываются.

## Д3. Деление на ноль зависает намертво

При нулевом делителе `gcd(base, 0) = |base|`, после сокращения делитель
остаётся нулём, и цикл `while (divisor % 5 == 0)` крутится вечно: `0 ~/ 5`
снова ноль. Не исключение, не мусор — зависание.

**Правка:** проверка в начале `operator /`, `UnsupportedError('division by
zero')` — ровно то, что уже бросают `Fraction` и `Division`. Оба семейства.

## Д4. `Decimal.toBigInt` теряет порядок величины

`toBigInt() => truncate().base` возвращает **базу**, а не значение: при
отрицательном масштабе `Decimal(1) << 3` — это база `1` при масштабе `-3`,
и метод отвечает `1` вместо `1000`.

**Правка:** домножать на `10^-scale`, как это уже делает `ShortDecimal.toInt`.
После `truncate` масштаб всегда `<= 0`, поэтому показатель неотрицателен.

одна строка. Д2 — самая крупная, идёт последней.
