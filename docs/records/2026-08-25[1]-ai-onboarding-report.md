# Первичная настройка проекта под работу с ИИ

## Зачем

Сессия агента может оборваться в любой момент. До этой работы следующая
сессия начинала с нуля: в репозитории не было ни описания устройства пакета,
ни записи о том, чем занимались. Задача — сделать так, чтобы новая сессия
поднималась сама, из файлов, одинаково для Claude Code и Codex CLI.

## Что сделано

### Точка входа

`AGENTS.md` в корне — единственный документ, который агент обязан прочитать
первым. Codex CLI читает его сам; Claude Code приходит к нему через
`CLAUDE.md`, где нет ничего, кроме строки `@AGENTS.md`. Одна точка входа на
два инструмента: расхождению между «инструкциями для Claude» и «инструкциями
для Codex» просто негде возникнуть.

В `AGENTS.md` описаны: протокол старта сессии, протокол во время работы,
протокол завершения эпизода, карта документов, правила именования записей в
`docs/records/`, язык документов, границы коммита и порядок публикации на
pub.dev.

### Разделение документов по времени жизни

Ключевое решение — четыре документа, у каждого своё время жизни, и они не
пересекаются:

| Документ | Время жизни | Кто пишет |
|:--|:--|:--|
| `docs/handoff.md` | «сейчас» | агент |
| `docs/backlog.md` | «потом» | владелец |
| `docs/records/` | «раньше» | агент |
| `docs/architecture.md`, `docs/conventions.md` | «всегда» | агент |

Из этого следуют запреты, записанные явно, потому что нарушать их удобно и
поэтому легко:

- в `handoff.md` не пересказывать `git log`, не разбирать законченные эпизоды
  и не хранить пожелания владельца;
- в `backlog.md` агенту не писать вообще ничего своего — только читать,
  предлагать взять в работу и удалять сделанное;
- в `architecture.md` не держать ничего быстроменяющегося.

### `docs/architecture.md`

Написан с нуля по коду. Разобраны: два параллельных семейства типов и почему
они не связаны общим интерфейсом; представление `base` × 10^(−`scale`) и
смысл отрицательного `scale`; выравнивание `_align` как основа всех бинарных
операций и вытекающий из него инвариант равенства по значению; ленивая
упаковка с кешем у `Decimal` против немедленной у `ShortDecimal` и почему у
`int` выбора нет; деление только точное и роль `DecimalDivideException` как
штатной развилки, а не ошибки; `Fraction`, `Division`, `fastGcd` в обход
[dart-lang/sdk#46180](https://github.com/dart-lang/sdk/issues/46180); границы
`ShortDecimal`; таблица исключений; устройство тестов и стенда `example/`.

Отдельно зафиксированы осознанные расхождения API двух семейств
(`shiftLeft`, `toBigInt`/`toInt`, `optimize`, набор расширений) — чтобы их не
принимали за недосмотр и не «чинили».

### `docs/conventions.md`

Соглашения выведены из существующего кода, а не назначены сверху: `final
class` без иерархий, `@immutable` с явным исключением для `Decimal`,
`@visibleForTesting` на внутреннем представлении, имена приватных
конструкторов `_asIs`/`_pack`, относительные импорты внутри `lib/src/`,
extension'ы с суффиксом `Internals` в `helpers.dart`, `// TODO(vi.k):`.

Главный практический пункт — таблица зеркальных правок: файл в
`lib/src/decimal/` почти всегда требует парной правки в
`lib/src/short_decimal/`. Плюс правила тестов (проверять через хелперы,
которые смотрят и на `base`/`scale`, а не только на `toString()`) и формат
коммитов по существующей истории.

### `docs/backlog.md` и судьба `TODO.md`

`TODO.md` из корня перенесён в `docs/backlog.md` дословно и удалён из корня.
Это записи владельца, поэтому текст не переписывался и не переводился —
перенесена только их прописка. Двух списков задач в проекте теперь нет.

### `.pubignore`

`AGENTS.md`, `CLAUDE.md`, `docs/` и `.vscode/` исключены из публикуемого
архива: это рабочие документы, а не часть пакета. Поскольку `.pubignore`
перекрывает `.gitignore`, в него продублированы `.dart_tool/` и
`pubspec.lock`. Проверено `dart pub publish --dry-run`: архив 45 КБ,
0 предупреждений.

## Состояние кодовой базы на момент работы

Код не менялся — работа целиком документарная. Замеры на Dart 3.13.0:
`dart test` — 60 тестов, все проходят; `dart format` — чисто; `dart analyze` —
3 замечания, ни одного в логике пакета.

Заодно всплыло и записано в `docs/handoff.md`:

- секция `exclude` в обоих `analysis_options.yaml` записана картой вместо
  списка и потому не работает (последствий нет — перечисленных каталогов в
  проекте не существует);
- `Decimal.toStringAsExponential` и `Decimal.toStringAsPrecision` объявлены и
  бросают `UnimplementedError`, а у `ShortDecimal` отсутствуют вовсе;
- `ShortDecimalDivideException.toString()` печатает только дробь — строка с
  `quotientWithRemainder` закомментирована без объяснения, у
  `DecimalDivideException` печатаются обе.

Ни одно из этих наблюдений не исправлялось: работа была про настройку, а не
про правку кода.

  под ИИ отношения не имеют.

  ждут решения владельца.
