# Отчёт: `--passes=N`

## Зачем

Медиана пяти прогонов защищает от одного испорченного замера, но не от
всплеска нагрузки, который накрыл всю серию. Серия одного бенчмарка — около
одиннадцати секунд; помеха такой длины портит все пять прогонов сразу, медиана
врёт, а разброс при этом выглядит приличным. Отличить это можно только замером
в другое время.

Процедура была найдена при обновлении конкурентов и записана в
`docs/conventions.md`, но исполнялась руками: девять кусков по тегам, дважды,
потом сведение по минимуму скриптом на Python вне репозитория. Воспроизвести
цифры README мог только тот, кто прочитал соглашения и повторил всё это.

## Что сделано

**Проход — это весь набор целиком.** Внешний цикл в `run()` гоняет все тесты
N раз; после каждого прохода `endPass()` закрывает его: медиана прогонов
уходит в `passes`, список прогонов очищается.

**В ячейку сводки идёт лучший проход**, а не средний и не последний:
`score => passes.reduce(min)`. Обоснование то же, что и было: помеха может
замер только замедлить, никогда не ускорить.

Разделение по времени получается само: второй проход доходит до конкретного
бенчмарка минут через двадцать после первого — этим они и независимы.

Внутри прохода ничего не изменилось: `--runs` по-прежнему пять, медиана
по-прежнему защищает проход от одного плохого замера, разброс по-прежнему
печатается рядом.

Мелочи, без которых флаг был бы неудобным:

- значения набора печатаются только в первом проходе — во втором они те же;
- пара «пакет × тест», которой не оказалось в сводке после первого прохода,
  в следующих не пересоздаётся: пакет эту операцию не умеет, и переспрашивать
  нечего;
- под сводкой печатается либо «each cell is the best of N passes», либо, при
  одном проходе, предупреждение, что для цифр, которые собираются цитировать,
  нужен `--passes=2`.

По умолчанию проход один: посмотреть, где стоит пакет, хватает и его, а
двойная цена должна быть осознанной.

## Проверка

`round to-double --passes=2 --runs=2`, оба прохода видны в логе:

| Строка | Проход 1 | Проход 2 | В сводке |
|:--|--:|--:|--:|
| `round`, `decimal` | 3.483 | 3.572 | **3.483** |
| `round`, наш `Decimal` | 3.021 | 3.050 | **3.021** |
| `to-double`, `big_decimal` | 0.902 | 0.872 | **0.872** |
| `to-double`, наш `Decimal` | 0.744 | 0.737 | **0.737** |

Минимум берётся по каждой ячейке отдельно, а не по проходу целиком, — видно по
`to-double`, где лучшим оказался второй проход, а в `round` первый.

Непроходимые пары (`decimal_type` без `round`, `big_double` без него же)
напечатаны один раз и во втором проходе не повторяются.

## Чего не делалось

**Таблицы README не перемерялись.** Цифры в них получены ровно этой
процедурой — два прохода, лучшая из двух медиан, — просто исполненной руками.
Флаг ничего не меняет в том, что и как измеряется, поэтому новый прогон дал бы
те же числа с точностью до шума, а стоил бы часа. Команда под таблицей в
README обновлена на `--passes=2`.

Единственное отличие ручного варианта от флага: руками набор гонялся девятью
кусками в разных процессах, флаг гоняет оба прохода в одном. Что состояние
процесса на цифры не влияет, проверено отдельно при обновлении конкурентов:
изолированный прогон `raw-view-int` дал то же, что и он же после двух тяжёлых
тестов.
