# Случаи для проверки конкурентов

Восемнадцать мест, найденных двумя ревью, — готовый набор проб. Если конкурент
падает на тех же — находки универсальны, и это довод в пользу нашего стенда;
если не падает — у него там сделано лучше, и стоит посмотреть как.

Проверять в первую очередь `precise_decimal`: он единственный проходит все 35
тестов стенда без единого неверного ответа, и он же метит в полное
соответствие General Decimal Arithmetic, где на большинство этих вопросов есть
готовый ответ.

## Применимо к любому пакету на BigInt

| Что проверять | Наш случай |
|:--|:--|
| канонизация меняет значение | `(10 × 10^(2^63−1)) × 10` — хранится с масштабом `−2^63`, а нормализованное отдаёт `1 × 10^(2^63−1)` |
| факторизация делителя заворачивает масштаб | `(1 >> 2^63−1) / 2` — масштаб уходит в минус |
| быстрый путь деления считает показатель до проверки | `divide(…, scaleOnInfinitePrecision: 2)` отвечает `0.23`, пока соседние формы бросают |
| равные значения ведут себя по-разному | `ten` как `10 × 10^0` против `1 × 10^1`: деление и `pow` расходились |
| двойное округление при сбросе цифр | `9000000013530038636/41` до 20 знаков: `.85365` не должно стать `.8` |
| разбор длиннее предела | строка с двумя миллионами дробных знаков: принимается ли, и работают ли потом операции |
| печать исключения деления | бросает ли `toString` самого исключения |
| экспоненциальная печать очень большого числа | `1e1000001` в `toStringAsExponential(0)` |
| знак нуля | `0 / −5` — должно быть `−0.0`, как в самом Dart |
| точность `toDouble` на 20+ знаках | наш набор: `decimal` промахивается на трёх из десяти, мы — ни разу |

## Применимо только к пакетам с типом на int64

У `precise_decimal` такого типа нет, так что эти — для будущих конкурентов или
для сравнения с Java `BigDecimal` с его `intCompact`:

| Что проверять | Наш случай |
|:--|:--|
| сумма, у которой каноническая форма помещается | `int.max + 3` = `922337203685477581 × 10` |
| частное, представимое только вне int64 | `1 / 2^62` — не должно возвращаться с чужим знаком |
| `toInt` за границей | `1e19` и `−1e19`: кламп, заворачивание или бросок |
| дроби на границе | `2/1 ÷ (−5/2^62)` и `2^62/1 × 2/5` |
| `inverse` минимального целого | тип броска |
| `pow` отрицательной степени, где основание переполнилось | `int.min ^ −3` |

## Как проверять

По процедуре из `2026-08-27[3]`: ожидаемые ответы считать точной рациональной
арифметикой **вне Dart**, а не сверять пакеты друг с другом — иначе две ошибки
согласятся между собой. Пробы держать вне репозитория, как в прошлые разы.
