## Чем занимаемся

Ревью закончено, спека принята, **работа по ней не начата**.

Владелец решил три развилки, они определяют объём:

1. **Две ступени: 1.2.0, затем 2.0.** Все пятнадцать дефектов чинятся без слома
   API, недостающее добавляется аддитивно. Ломающее (оператор деления,
   изменяемость `Decimal`, открытие представления) — в отдельную 2.0.
2. **Переполнение `ShortDecimal` остаётся молчаливым.** Чинятся только случаи,
   где переполняется промежуточное значение при том, что аргументы и
   канонический результат в int64 укладываются.
3. **Общий интерфейс `FixedPoint` плюс тест симметрии.** Реализации остаются
   раздельными. В 1.2.0 интерфейс внутренний; имя выбрано с расчётом на то, что
   когда-нибудь он может стать публичным супертипом в роли `num`.
4. **Сверка с `decimal` — обязательная часть тестовой сюиты**, а не разовое
   упражнение: она даёт красный на восьми дефектах из пятнадцати.

Следующий шаг — волна 0 из плана: тестовый фундамент, без единой правки в
`lib/`. Порядок здесь не вкусовой: тесты сейчас сверяют внутреннее
представление в 245 местах, а быстрый путь точного деления даёт тот же
результат в другой форме. Пока тесты не переписаны, любая оптимизация выглядит
как поломка.

Документы: `docs/records/2026-08-25[3]-package-review.md` (находки),
`[4]-package-rework-design.md` (устройство), `[5]-package-rework-plan.md`
(порядок работ).

## Известные пробелы

Полный разбор — в `docs/records/2026-08-25[3]-package-review.md`. Здесь только
то, что определяет ближайшие решения.

- **13 подтверждённых дефектов**, из них 4 Critical: деление на отрицательное
  бросает исключение вместо результата; `_pow10` переполняется и ломает
  сравнение, сортировку и округление `ShortDecimal`; деление на ноль зависает
  намертво; `Decimal.toBigInt()` теряет порядок величины.
- **Заглавный API деления медленнее конкурента.** `1/3` через `operator /` +
  `try/catch` — 1971 нс против 1437 нс у `decimal`. Тотальный путь
  `divideToFraction().round(6)` даёт 565 нс, но спрятан в README.
- **Два семейства разошлись в 25 местах.** Аргумент про цену полиморфизма
  проверен измерением: общий интерфейс стоит 0 %, дорога только общая
  реализация через дженерики (2×).
- Покрытие тестами 74.7 %; у `ShortDecimal` целиком отсутствуют группы
  `compare` и `toStringAsFixed`. Тесты фиксируют внутреннее представление, из-за
  чего любая оптимизация деления обязана их ломать.
- `toStringAsExponential`/`toStringAsPrecision` у `Decimal` бросают
  `UnimplementedError`, у `ShortDecimal` отсутствуют вовсе.
- `example/README.md` — заглушка от `dart create`; реального примера
  использования в пакете нет.
