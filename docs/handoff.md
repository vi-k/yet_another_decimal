### Сделано и смержено (`dd481e7`)

| Файл | Что делает |
|:--|:--|
| `test/support/reference.dart` | точная рациональная арифметика на `BigInt` и детерминированный генератор |

| `test/competitors_test.dart` | сверка каждой операции с пакетом `decimal` плюс список осознанных расхождений |
| `test/defects_test.dart` | воспроизводители всех пятнадцати дефектов |

В `pubspec.yaml` добавлена `dev_dependency` на `decimal ^3.2.6` — она нужна
сверке с конкурентом.

Три решения, принятых по ходу, чтобы их не пересматривали вслепую:

- **Красных тестов в `main` нет.** План требовал пятнадцать красных, но красный
  `main` — плохая практика. Воспроизводители написаны с **корректным**
  ожиданием и помечены `skip: 'ДN: …'`. **Снятие `skip` — критерий готовности
  каждой правки**, и его видно в диффе.
- **Эталонная модель не использует код пакета.** Иначе она повторяла бы его
  ошибки вместо того, чтобы их ловить. `Ref.parse` разбирает строку сам, не
  через `Decimal.parse`.
- **Генератор детерминирован**, своё зерно на каждый тест; номер случая и
  значения печатаются в `reason`, поэтому падение воспроизводится сразу.

Property-тест уже окупился: самостоятельно нашёл Д1 на случае `-90.2649 / -3`,
которого не было ни в одном ручном списке.

### Осталось по волне 0

Правки существующего `test/yet_another_decimal_test.dart` (4336 строк):

1. **Убрать сверку `base`/`scale` из арифметических проверок**, оставить её

   упавший третий случай из тридцати семи скрывает остальные и не сообщает,
   какой именно упал.
3. Разбить файл по темам и семействам; завести у `ShortDecimal` отсутствующие
   группы `compare` и `toStringAsFixed` — их пропажа и есть причина 30 %

## Решения владельца, действующие сейчас

Обоснование каждого — в `docs/records/2026-08-25[4]-package-rework-design.md`.

1. **Две ступени: 1.2.0, затем 2.0.** Все пятнадцать дефектов чинятся без слома
   API, недостающее добавляется аддитивно. Ломающее — отдельно в 2.0.
2. **Переполнение `ShortDecimal` остаётся молчаливым.** Чинятся только случаи,
   где переполняется промежуточное значение при том, что аргументы и
   канонический результат в int64 укладываются.
3. **Общий интерфейс `FixedPoint` плюс тест симметрии**, реализации остаются
   раздельными. В 1.2.0 интерфейс внутренний, не экспортируется. Имя выбрано с
   расчётом на то, что когда-нибудь он может стать публичным супертипом в роли
   `num` для `int` и `double`. Межсемейных операций не будет: смешивание — через
   явный мост.
4. **Сверка с `decimal` — обязательная часть тестовой сюиты**, а не разовое
   упражнение.

## Известные пробелы

Полный разбор — в `docs/records/2026-08-25[3]-package-review.md`. Здесь только
то, что определяет ближайшие решения.

- **15 подтверждённых дефектов**, из них 4 Critical: деление на отрицательное
  бросает исключение вместо результата; `_pow10` переполняется и ломает
  сравнение, сортировку и округление `ShortDecimal`; деление на ноль **зависает
  намертво**; `Decimal.toBigInt()` теряет порядок величины. Все воспроизведены
  запуском, все имеют тест в `test/defects_test.dart`.
- **В восьми случаях из десяти все три конкурента отвечают правильно, а мы
  нет.** Сверка с `decimal`, `big_decimal` и `fixed` — в ревью.
- **Заглавный API деления медленнее конкурента.** `1/3` через `operator /` плюс
  `try/catch` — 1971 нс против 1437 нс у `decimal`. Тотальный путь
  `divideToFraction().round(6)` даёт 565 нс, но спрятан в README.
- **Два семейства разошлись в 25 местах.** Аргумент про цену полиморфизма
  проверен измерением: общий интерфейс стоит 0 %, дорога только общая
  реализация через дженерики (2×).
- Покрытие тестами было 74.7 % до волны 0; у `ShortDecimal` целиком отсутствуют
  группы `compare` и `toStringAsFixed`.
- `toStringAsExponential`/`toStringAsPrecision` у `Decimal` бросают
  `UnimplementedError`, у `ShortDecimal` отсутствуют вовсе.
- Таблица бенчмарков в README устарела: `add` и `multiply` сейчас в пределах
  шума, а `divide-large` мы проигрываем.
- `example/README.md` — заглушка от `dart create`; реального примера
  использования в пакете нет.
