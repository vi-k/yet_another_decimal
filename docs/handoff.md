Сюита: 79 проходят, 41 помечен `skip` с номером дефекта.

**Принятое по ходу решение.** План требовал пятнадцать красных тестов, но
красный `main` — плохая практика. Поэтому воспроизводители написаны с
**корректным** ожиданием и помечены `skip: 'ДN: …'`. Снятие `skip` — критерий
готовности каждой правки. Красных тестов в `main` не появляется.

Эталонная модель написана **без использования кода пакета** — иначе она
повторяла бы его ошибки вместо того, чтобы их ловить. Property-тест уже
доказал свою полезность: самостоятельно переоткрыл Д1 на случае
`-90.2649 / -3`.

Осталось по волне 0 (правки существующего `test/yet_another_decimal_test.dart`
на 4336 строк):

1. Убрать сверку `base`/`scale` из арифметических проверок — оставить только в
   `parse`, `toString`, `optimize`. Сейчас представление сверяется 245 раз, и
   из-за этого быстрый путь точного деления из волны 3 обязан ломать тесты.
2. Табличные циклы разложить в отдельные `test` или добавить `reason`.
3. Разбить файл по темам и семействам; завести у `ShortDecimal` отсутствующие
   группы `compare` и `toStringAsFixed`.

## Известные пробелы

Полный разбор — в `docs/records/2026-08-25[3]-package-review.md`. Здесь только
то, что определяет ближайшие решения.

- **13 подтверждённых дефектов**, из них 4 Critical: деление на отрицательное
  бросает исключение вместо результата; `_pow10` переполняется и ломает
  сравнение, сортировку и округление `ShortDecimal`; деление на ноль зависает
  намертво; `Decimal.toBigInt()` теряет порядок величины.
- **Заглавный API деления медленнее конкурента.** `1/3` через `operator /` +
  `try/catch` — 1971 нс против 1437 нс у `decimal`. Тотальный путь
  `divideToFraction().round(6)` даёт 565 нс, но спрятан в README.
- **Два семейства разошлись в 25 местах.** Аргумент про цену полиморфизма
  проверен измерением: общий интерфейс стоит 0 %, дорога только общая
  реализация через дженерики (2×).
- Покрытие тестами 74.7 %; у `ShortDecimal` целиком отсутствуют группы
  `compare` и `toStringAsFixed`. Тесты фиксируют внутреннее представление, из-за
  чего любая оптимизация деления обязана их ломать.
- `toStringAsExponential`/`toStringAsPrecision` у `Decimal` бросают
  `UnimplementedError`, у `ShortDecimal` отсутствуют вовсе.
- `example/README.md` — заглушка от `dart create`; реального примера
  использования в пакете нет.
