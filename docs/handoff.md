## Чем занимаемся

**Идёт полное ревью пакета с последующей спекой на переработку.** Задача от
владельца: привести пакет в порядок — найти баги, дописать недостающее,
исправить кривое, написать тесты, снабдить документацией.

Рамка, заданная владельцем и определяющая приоритеты: **пакет существует ради
производительности выше, чем у конкурентов, при сохранении качества. Главный
конкурент — `decimal`.** Любое предложение из ревью проверяется этим: не
съедает ли оно скорость, ради которой пакет и написан.

Этап 1 (в работе): шесть независимых потоков ревью.

| Поток | Зона |
|:--|:--|
| bug-hunter | `lib/src/decimal/**`, `helpers.dart` |
| bug-hunter | `lib/src/short_decimal/**` |
| performance-review | весь пакет + методология бенчмарков в `example/` |
| architecture-review | архитектура и качество публичного API |
| test-review | полнота и качество `test/` |
| Codex | независимое второе мнение по всему пакету |

Всем потокам запрещено менять файлы проекта — это только чтение.
Параллельно прогоняются бенчмарки (`example/bin/benchmark.dart all`), вывод —
в scratchpad-файле `bench.txt`.

Этап 2 (после): свести находки в отчёты `docs/records/`, снять с владельца
развилки, которые меняют объём работ (ломать ли API, что делать с
дублированием двух семейств, что с `ShortDecimal`), и написать спеку.

Если сессия оборвалась на этапе 1 — потоки ревью придётся запустить заново,
их результаты нигде не сохраняются до сведения в `docs/records/`.

## Известные пробелы

Полный разбор — в `docs/records/2026-08-25[3]-package-review.md`. Здесь только
то, что определяет ближайшие решения.

- **13 подтверждённых дефектов**, из них 4 Critical: деление на отрицательное
  бросает исключение вместо результата; `_pow10` переполняется и ломает
  сравнение, сортировку и округление `ShortDecimal`; деление на ноль зависает
  намертво; `Decimal.toBigInt()` теряет порядок величины.
- **Заглавный API деления медленнее конкурента.** `1/3` через `operator /` +
  `try/catch` — 1971 нс против 1437 нс у `decimal`. Тотальный путь
  `divideToFraction().round(6)` даёт 565 нс, но спрятан в README.
- **Два семейства разошлись в 25 местах.** Аргумент про цену полиморфизма
  проверен измерением: общий интерфейс стоит 0 %, дорога только общая
  реализация через дженерики (2×).
- Покрытие тестами 74.7 %; у `ShortDecimal` целиком отсутствуют группы
  `compare` и `toStringAsFixed`. Тесты фиксируют внутреннее представление, из-за
  чего любая оптимизация деления обязана их ломать.
- `toStringAsExponential`/`toStringAsPrecision` у `Decimal` бросают
  `UnimplementedError`, у `ShortDecimal` отсутствуют вовсе.
- `example/README.md` — заглушка от `dart create`; реального примера
  использования в пакете нет.
