# Соглашения

Как здесь принято писать. Правила выведены из существующего кода — если
что-то расходится с кодом, прав код, а этот файл надо поправить.

## Язык

- По-русски: `AGENTS.md`, `docs/**`, общение с владельцем.
- По-английски: `README.md`, `CHANGELOG.md`, dartdoc-комментарии в `lib/`,
  комментарии внутри кода, `TODO`, сообщения коммитов, тексты исключений.

## Dart

Форматирование — `dart format` без исключений, ширина по умолчанию (80).
Проверка: `dart format --output=none --set-exit-if-changed .`

Анализ — `analysis_options.yaml` в корне (и отдельный, такой же, в
`example/`). Он строже, чем `package:lints/recommended`: включены
`strict-casts`, `strict-inference`, `strict-raw-types`, часть info поднята до
warning и error. `dart analyze` должен проходить без новых замечаний.

Правила, которых стоит держаться:

- Классы верхнего уровня — `final class`. Иерархий наследования в пакете нет.
- `@immutable` там, где класс действительно неизменяем. `Decimal` — исключение
  с явным обоснованием в коде (кеш `_packed`), и именно поэтому в нём стоят
  точечные `// ignore: avoid_equals_and_hash_code_on_mutable_classes`.
- Внутреннее представление (`base`, `scale`) помечается
  `@visibleForTesting`, а не делается приватным: тесты проверяют не только
  значение, но и форму его хранения.
- Приватные конструкторы `_asIs` (без нормализации) и `_pack` (с
  нормализацией) — принятые в пакете имена, держаться их.
- Импорты — относительные внутри `lib/src/` (`prefer_relative_imports` поднят
  до warning), `package:` — только для внешних зависимостей.
- Вспомогательные функции, нужные только пакету, живут в `lib/src/helpers.dart`
  как extension'ы с суффиксом `Internals`.
- `ignore`-комментарии — точечные, с причиной, если она не очевидна.
  Файловых `ignore_for_file` в `lib/` нет.

### Публичный API

Всё, что выходит наружу, экспортируется из `lib/yet_another_decimal.dart`.
Новые публичные символы добавлять только осознанно: пакет опубликован, и
любое расширение API придётся поддерживать.

Каждый публичный член снабжается dartdoc-комментарием по-английски. Стиль —
как в `Decimal`: первая строка — краткое описание, дальше при необходимости
пример в блоке ```dart. Ссылки на другие члены — в квадратных скобках
(`[base]`, `[Decimal]`).

Незаконченное помечается `// TODO(vi.k): ...` — этот формат уже используется
в коде, `flutter_style_todos` поднят до warning.

### Симметрия двух семейств

`Decimal` и `ShortDecimal` — параллельные реализации. Правка в одном почти
всегда требует зеркальной правки в другом:

| Правишь | Проверь также |
|:--|:--|
| `lib/src/decimal/decimal.dart` | `lib/src/short_decimal/short_decimal.dart` |
| `lib/src/decimal/fraction.dart` | `lib/src/short_decimal/short_fraction.dart` |
| `lib/src/decimal/division.dart` | `lib/src/short_decimal/short_division.dart` |

Если симметрию сознательно нарушают — написать в коде почему.

## Тесты

Всё в одном файле `test/yet_another_decimal_test.dart`. Структура групп
повторяет структуру типов: `Decimal`, `Fraction`, `Division`, `ShortDecimal`,
`ShortFraction`, `ShortDivision`.

- Проверять через хелперы из шапки файла (`expectDecimal`,
  `expectShortDecimal`, `expectFraction`, `expectDivision`, `expectDivide`,
  `expectDouble`), а не голым `expect`. Хелперы заодно проверяют внутреннее
  представление — передавать `base`, `scale`, `fractionDigits` там, где форма
  хранения существенна.
- Новую операцию покрывать в обоих семействах.
- Для `ShortDecimal` отдельно покрывать граничные значения `int`.
- Где `double` теряет точность, а пакет — нет, фиксировать это через
  `expectDouble(..., isValid: false)`.

Запуск: `dart test`.

## Бенчмарки

`example/` — не примеры использования, а стенд сравнения скорости. Новый
сравниваемый пакет добавляется файлом-адаптером в `example/lib/src/tests/` и
записью в `example/lib/src/packages.dart`. Цифры из прогона идут в таблицы
`README.md` — при обновлении таблиц указывать, на чём мерили.

## Коммиты

По-английски, повелительное наклонение, одна строка, без точки в конце — как
в существующей истории:

```
Add big_double to benchmarks for speed comparision
Fix links in README
Update dependencies
```

Не смешивать в одном коммите правки логики, форматирование и правки README —
в истории это уже разделено (`Format` отдельным коммитом).

**Не коммитить чужие правки вместе со своими.** Добавлять файлы поимённо
(`git add <файл>`), не `git add -A`, не `git commit -a`.

Мержить прямо в `main`, без PR.

## Версии и CHANGELOG

Версия — в `pubspec.yaml`, семантическая. Тег релиза — `vX.Y.Z`.

`CHANGELOG.md` по-английски, новые записи сверху. В нём принято объединять
близкие патч-версии в один заголовок диапазоном:

```markdown
## 1.1.0-1.1.2

- Update dependencies.
- Fix links in README.
```

Порядок публикации и правила разрешения на неё — в `AGENTS.md`, раздел
«Публикация на pub.dev».
